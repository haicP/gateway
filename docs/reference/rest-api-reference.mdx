The lightweight runtime exposes only service metadata, health, and trace
request-record APIs under `/api`.

Provider proxy routes such as `/llm/...` are configured in YAML and pass through
to upstream providers after stripping the configured prefix.

## Base URL

- Default local base URL: `http://localhost:8080`
- Response content type: `application/json`
- Timestamps use UTC RFC3339.
- Responses include `X-OngoingAI-Correlation-ID`.

## Endpoints

| Method | Path | Success |
| --- | --- | --- |
| `GET` | `/` | `200` service metadata |
| `GET` | `/api/health` | `200` health summary |
| `GET` | `/api/traces` | `200` paginated trace list |
| `GET` | `/api/traces/:id` | `200` trace detail |
| `GET` | `/api/traces/:id/replay` | `200` replay checkpoints |
| `POST` | `/api/traces/:id/fork` | `200` fork lineage headers |

## Health

`GET /api/health` response fields include:

| Field | Description |
| --- | --- |
| `status` | Health status |
| `version` | Gateway version |
| `uptime_sec` | Process uptime |
| `storage_driver` | `sqlite` or `postgres` |
| `storage_path` | SQLite database path when configured |
| `trace_count` | Stored trace count when available |
| `db_size_bytes` | SQLite file size when available |

## Trace List

`GET /api/traces` query parameters:

| Parameter | Description |
| --- | --- |
| `trace_group_id` | Filter by lineage group |
| `thread_id` | Filter by lineage thread |
| `run_id` | Filter by lineage run |
| `provider` | Filter by provider name |
| `model` | Filter by model |
| `api_key_hash` | Filter by upstream API key hash |
| `status` | Filter by HTTP status code |
| `min_tokens` | Minimum total tokens |
| `max_tokens` | Maximum total tokens |
| `from` | Start time, RFC3339 or `YYYY-MM-DD` |
| `to` | End time, RFC3339 or `YYYY-MM-DD` |
| `limit` | Page size, max `200` |
| `cursor` | Cursor from prior response |

Example:

```bash
curl "http://localhost:8080/api/traces?provider=openai&limit=20"
```

## Trace Detail

`GET /api/traces/:id` returns route, method, status, timing, model, token
metadata, request/response headers, optional captured bodies, and metadata.

Credential headers are redacted before storage. Body capture is controlled by
`tracing.capture_bodies`.

## Replay And Fork

`GET /api/traces/:id/replay` returns recorded lineage checkpoints for a trace
group.

`POST /api/traces/:id/fork` creates lineage headers that can be sent on a
subsequent proxied request.

## Errors

Error responses use:

```json
{
  "error": "message"
}
```
