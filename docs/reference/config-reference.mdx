Use `ongoingai.yaml` to configure server binding, storage, provider routes,
request recording, request-detail backup, and retention cleanup.

## Baseline Config

```yaml
server:
  host: 0.0.0.0
  port: 8080

storage:
  driver: sqlite
  path: ./data/ongoingai.db
  # dsn: postgres://user:password@localhost:5432/ongoingai?sslmode=disable

providers:
  llm:
    upstream: https://api.openai.com
    prefix: /llm

tracing:
  capture_bodies: false
  body_max_size: 1048576
  retention:
    days: 14
    cleanup_enabled: false
    cleanup_daily_at: "02:00"
    cleanup_timezone: Local

dashboard:
  enabled: false

backup:
  request_details:
    enabled: false
    timezone: Local
    daily_at: "02:00"
    temp_dir: ./data/backup-tmp
    page_size: 500
    shard_max_bytes: 209715200
    retry:
      max_attempts: 5
      initial_backoff_ms: 1000
      max_backoff_ms: 30000
    s3:
      bucket: ""
      prefix: request-details
      region: ""
      endpoint: ""
      force_path_style: false
```

## Server

| Field | Default | Description |
| --- | --- | --- |
| `server.host` | `0.0.0.0` | Listen host |
| `server.port` | `8080` | Listen port |

## Storage

| Field | Default | Description |
| --- | --- | --- |
| `storage.driver` | `sqlite` | `sqlite` or `postgres` |
| `storage.path` | `./data/ongoingai.db` | SQLite path |
| `storage.dsn` | empty | Postgres DSN |

## Providers

`providers` is a map of provider names to reverse-proxy routes.

## Dashboard

| Field | Default | Description |
| --- | --- | --- |
| `dashboard.enabled` | `false` | Serve the local trace dashboard at `/dashboard`. For multi-instance deployments, enable it on only the instance intended to expose the panel. |

| Field | Description |
| --- | --- |
| `providers.<name>.upstream` | Upstream base URL with scheme and host |
| `providers.<name>.prefix` | Public gateway prefix to strip before forwarding |

Provider names must use lowercase letters, numbers, hyphen, or underscore.
Prefixes must start with `/`, must not be `/`, must not overlap `/api`, and
must not overlap each other.

## Tracing

| Field | Default | Description |
| --- | --- | --- |
| `tracing.capture_bodies` | `false` | Store captured request and response bodies |
| `tracing.body_max_size` | `1048576` | Max captured bytes per body; `0` means unbounded prefix capture |
| `tracing.retention.days` | `14` | Number of days to keep when cleanup is enabled |
| `tracing.retention.cleanup_enabled` | `false` | Enable scheduled cleanup |
| `tracing.retention.cleanup_daily_at` | `02:00` | Daily cleanup time, `HH:MM` |
| `tracing.retention.cleanup_timezone` | `Local` | IANA timezone for cleanup scheduling |

Credential headers are redacted before trace storage. Body capture is opt-in.

## Backup

`backup.request_details` controls scheduled request-detail export to
S3-compatible object storage.

| Field | Default | Description |
| --- | --- | --- |
| `enabled` | `false` | Enable request-detail backup |
| `timezone` | `Local` | IANA timezone for daily backup windows |
| `daily_at` | `02:00` | Daily backup start time |
| `temp_dir` | `./data/backup-tmp` | Local temporary shard directory |
| `page_size` | `500` | Trace page size while exporting |
| `shard_max_bytes` | `209715200` | Target max bytes per gzip NDJSON shard |
| `retry.max_attempts` | `5` | Upload retry attempts |
| `retry.initial_backoff_ms` | `1000` | Initial retry backoff |
| `retry.max_backoff_ms` | `30000` | Max retry backoff |
| `s3.bucket` | empty | Required when backup is enabled |
| `s3.prefix` | `request-details` | Object key prefix |
| `s3.region` | empty | S3 region |
| `s3.endpoint` | empty | Optional S3-compatible endpoint |
| `s3.force_path_style` | `false` | Enable path-style addressing |

## Validation

- `server.port` must be between `1` and `65535`.
- SQLite requires `storage.path`.
- Postgres requires `storage.dsn`.
- Backup enabled requires an S3 bucket, valid timezone, valid `daily_at`,
  non-empty temp dir, positive page/shard/retry values, and valid endpoint URL
  when set.
