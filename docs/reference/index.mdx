Use this section when you need exact names, fields, flags, and routes.
You can use these pages as canonical lookup material while operating or
integrating the gateway.

## Use this reference when

- You need exact config keys, defaults, and validation constraints.
- You need CLI command syntax for scripts and runbooks.
- You need API route parameters and response fields for integration code.
- You need to integrate with the lightweight proxy and trace APIs.

## Read in this order

1. [Config reference](/gateway/reference/config-reference) for YAML fields,
   defaults, and validation rules.
2. [Environment variable reference](/gateway/reference/env-var-reference) for
   env override names and parse behavior.
3. [CLI reference](/gateway/reference/cli-reference) for command usage, flags,
   and exit behavior.
4. [REST API reference](/gateway/reference/rest-api-reference) for endpoint
   contracts and request and response shapes.
5. [CLI JSON contracts](/gateway/reference/cli-json-contracts) for current
   machine-readable CLI contract status.
6. [Authorization reference](/gateway/reference/authorization-reference) for the
   lightweight runtime authorization boundary.
7. [接口说明](/gateway/reference/interface-guide) for a Chinese overview of all
   public HTTP interfaces and example usage.

## What this section covers

- Configuration schema and operational defaults.
- Environment variable override behavior.
- CLI command contracts.
- CLI JSON contract status.
- Authorization boundary for the lightweight runtime.
- API contracts for health, provider proxy, and trace request records.
- A Chinese interface guide for the lightweight gateway surface.

If a detail is missing, verify behavior in `openapi/openapi.yaml`,
`cmd/ongoingai/main.go`, `internal/api/`, and `internal/proxy/`.
